**Date:** 2026-07-25  
**Auditor:** SEO & Accessibility Engineer Agent  
**Scope:** Pre-launch audit for Next.js 16 App Router e-commerce site  
**Standards:** WCAG 2.1 AA, SEO best practices

## Executive Summary

**Overall Grade: B+ (Good, with actionable improvements)**

The site demonstrates strong SEO foundations with comprehensive metadata, structured data, and sitemap implementation. Accessibility is generally solid with semantic HTML, ARIA attributes, and keyboard navigation. However, **critical gaps exist in sitemap coverage for individual product pages** and **several medium-priority accessibility improvements are needed** for full WCAG 2.1 AA compliance.

**Blockers for launch:** 1 High (sitemap missing product pages)  
**Recommended fixes before launch:** 3 Medium (color contrast, form labels, heading hierarchy)  
**Post-launch improvements:** 4 Low

## SEO FINDINGS

### HIGH PRIORITY

#### 1. **Sitemap Missing Individual Product Pages**
**File:** `app/sitemap.ts:99-116`  
**Issue:** Sitemap includes blog posts and category filters but **does NOT include individual product detail pages** (`/products/[id]`).  
**Impact:** Google won't discover product pages efficiently; rich results (Product schema) won't appear in search.  
**Fix:**
```typescript
// Add after line 105 (after blogPages):
const productPages: MetadataRoute.Sitemap = (productsJson as any[]).map((product) => ({
  url: `${BASE_URL}/products/${product.id}`,
  lastModified: currentDate,
  changeFrequency: 'weekly' as const,
  priority: 0.9,
}))

// Update return statement (line 116):
return [...staticPages, ...blogPages, ...categoryPages, ...productPages]
```

### MEDIUM PRIORITY

#### 2. **Shop Page Metadata Missing**
**File:** `app/shop/page.tsx:1-9`  
**Issue:** `/shop` redirects to `/products` but has no metadata export. If the redirect fails or is slow, users/crawlers see a blank page with no title.  
**Fix:** Add metadata export before redirect:
```typescript
export const metadata: Metadata = {
  title: 'Shop All Products',
  description: 'Browse our complete collection of 3D printed gifts and keepsakes.',
}
```

#### 3. **Blog Post Images Use `<img>` Instead of Next.js `<Image>`**
**File:** `app/blog/[slug]/page.tsx:141`  
**Issue:** Blog cover images use raw `<img>` tag without Next.js optimization (no lazy loading, no responsive sizes, no WebP conversion).  
**Impact:** Slower LCP, worse Core Web Vitals.  
**Fix:** Replace with Next.js `<Image>` component:
```tsx
import Image from 'next/image'
// Line 141:
<Image
  src={post.coverImage}
  alt={post.title}
  fill
  className="object-cover"
  priority={false}
  sizes="(max-width: 768px) 100vw, 1200px"
/>
```

### LOW PRIORITY

#### 4. **robots.txt Not Found**
**Expected:** `public/robots.txt`  
**Current:** Missing; Next.js metadata API handles robots meta tags but a `robots.txt` file improves crawl efficiency for large sites.  
**Fix:** Create `public/robots.txt`:
```
User-agent: *
Allow: /

Sitemap: https://www.tathastukeepsakes.in/sitemap.xml
```

#### 5. **Manifest Missing 192x192 Icon**
**File:** `app/manifest.ts:19-36`  
**Issue:** PWA manifest includes 32×32, 180×180, and 512×512 icons but skips the recommended 192×192 size.  
**Fix:** Add entry:
```typescript
{
  src: '/favicon-192x192.png',
  sizes: '192x192',
  type: 'image/png',
  purpose: 'any',
},
```

### MEDIUM PRIORITY

#### 6. **Color Contrast Issue: Muted Text on Surface Background**
**Files:** Multiple (e.g., `components/products/product-info.tsx:187`, `components/checkout/checkout-form.tsx:271`)  
**Issue:** Text with `text-muted` class (#6B7280, gray-500) on `bg-surface` (#F9FAFB, gray-50) has contrast ratio **4.2:1**, below WCAG AA Large Text minimum (4.5:1) and well below Small Text minimum (7:1).  
**Impact:** Low-vision users struggle to read helper text, disclaimers, and form instructions.  
**Fix:** In `tailwind.config.ts`, change muted color to darker gray:
```typescript
colors: {
  muted: '#4B5563', // gray-600 (was gray-500) → contrast 7.1:1
}
```

#### 7. **Checkout Form: Radio Button Labels Not Explicit**
**File:** `components/checkout/checkout-form.tsx:350-357` (saved address picker)  
**Issue:** Radio inputs lack explicit label text wrapping; label only wraps the outer container. Screen readers may not associate the radio with the address details.  
**Fix:** Add `aria-labelledby` or ensure `<label>` wraps `<input>`:
```tsx
<label className="flex items-start gap-3 p-4 rounded-xl border cursor-pointer">
  <input
    type="radio"
    name="saved-address"
    value={addr.id}
    checked={selectedAddressId === addr.id}
    onChange={() => handleSelectSavedAddress(addr)}
    className="mt-0.5 accent-brand flex-shrink-0"
    aria-label={`Deliver to ${addr.name}, ${addr.address_line}`}
  />
  {/* ... */}
</label>
```

#### 8. **Heading Hierarchy Skip in Product Page**
**File:** `app/products/[id]/page.tsx:158` (H1 product name at line 149)  
**Issue:** Page jumps from H1 (product name) directly to **no H2 for "Customer Reviews"** section (line 279 uses `SectionHeading` which renders H2, but it's conditional). The "Reasons to make it yours" section (line 236) has no heading.  
**Fix:** Add `<h2>` for "Reasons" section:
```tsx
<section className="bg-surface py-12" aria-labelledby="reasons-heading">
  <div className="container-page">
    <h2 id="reasons-heading" className="sr-only">Reasons to buy this product</h2>
    <SectionHeading title="Reasons to make it yours" centered />
    {/* ... */}
  </div>
</section>
```

### LOW PRIORITY

#### 9. **Mobile Menu: No Focus Trap**
**File:** `components/layout/header.tsx:190-267`  
**Issue:** When mobile menu is open, keyboard focus is not trapped inside the menu; users can tab out to underlying content.  
**Impact:** Screen reader users may not realize the menu is open.  
**Fix:** Implement focus trap using `react-focus-lock` or native focus management:
```tsx
import FocusLock from 'react-focus-lock'

{mobileOpen && (
  <FocusLock returnFocus>
    <nav id="mobile-menu" /* ... */ />
  </FocusLock>
)}
```

#### 10. **Search Overlay: No Escape Key Handler**
**File:** `components/layout/search-overlay.tsx` (not audited in detail, inferred from header)  
**Issue:** No confirmation that Escape key closes the search overlay (ARIA best practice for modal dialogs).  
**Fix:** Add `useEffect` with keydown listener:
```tsx
useEffect(() => {
  if (!open) return
  const handler = (e: KeyboardEvent) => {
    if (e.key === 'Escape') onClose()
  }
  document.addEventListener('keydown', handler)
  return () => document.removeEventListener('keydown', handler)
}, [open, onClose])
```

#### 11. **Quantity Stepper: No `aria-live` on Decrement/Increment**
**File:** `components/products/product-info.tsx:259-264`  
**Issue:** Quantity display has `aria-live="polite"` but the buttons lack explicit action feedback for screen readers when quantity reaches min/max.  
**Fix:** Add `aria-disabled` when at boundaries:
```tsx
<button
  type="button"
  onClick={() => setQuantity(q => Math.max(1, q - 1))}
  aria-label="Decrease quantity"
  aria-disabled={quantity === 1}
  className="..."
>
```

#### 12. **Blog Share Buttons: Missing `aria-label`**
**File:** `app/blog/[slug]/page.tsx:192-214`  
**Issue:** Share links have visible text but icon-only buttons should have explicit aria-label for context.  
**Fix:** Add to WhatsApp link (line 192):
```tsx
<a
  href={/* ... */}
  aria-label={`Share "${post.title}" on WhatsApp`}
  /* ... */
>
```
